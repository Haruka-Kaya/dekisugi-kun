## 中身

| ファイル | 誰に | いつ |
|---|---|---|
| `01-保護者むけ説明.md` | 保護者 | 同意書と一緒に配る |
| `02-同意書.md` | 保護者 → 学校が回収 | 説明を読んでもらったあと |
| `03-先生むけ.md` | 先生・情報担当 | 最初の相談のとき |
| `04-Google問い合わせ下書き.md` | （社内用） | 学校で使うと決める前 |

## 順番

```
① 先生に 03 を渡して、やるかどうかを決めてもらう
      ↓
② 学校の情報担当に確認（Workspace for Education の制約が無いか）
      ↓
③ Google への確認を出す（04）※ 回答を待たずに④へ進んでよいが、記録は残す
      ↓
④ 学校が 01 + 02 を保護者へ配る
      ↓
⑤ 学校が 02 を回収・保管する。**開発者は受け取らない**
      ↓
⑥ 学校が「あいことば」を生徒に伝える
      ↓
⑦ 生徒がアプリを入れて、同意画面で「学校からもらって使います」を選ぶ
```

## 同意を誰が取るか

**ここを取り違えると全部が崩れます。**

| | 個人で使う場合 | 学校から配る場合 |
|---|---|---|
| 誰が同意するか | 本人（15歳以下なら保護者が横で） | **保護者が用紙に署名** |
| どこに残るか | 端末の中 | **学校が用紙を保管** |
| アプリの画面 | 「おうちの人といっしょに確認しました」 | 「学校からもらって使います」+ あいことば |

学校経由のとき、アプリは**端末で保護者確認を求めません。**
生徒が「保護者に確認しました」を押しても、押したのは生徒であって保護者ではないからです。
紙の同意より弱い記録で上書きしないよう、経路そのものを分けてあります。

**ただし越境移転の同意画面は、学校経由でも生徒に表示します。**
学校が取るのは保護者の同意であって、生徒が何も知らないまま使ってよい、
という意味ではありません。

## あいことば

- 学校ごとに1つ決めて、生徒に伝えます
- **学校を識別するためのものではありません。** サーバーには送っていません
- 「学校から配られた人だけが学校の経路に入る」ための鍵です
- 推測されにくければ何でも構いません（例: `sakura-2026`）

## あいことばと「クラスコード」は別物です

クラスで合計を出す機能（希望があれば）を使うときは、**別のコード**をお渡しします。

| | あいことば | クラスコード |
|---|---|---|
| 誰が決めるか | **学校** | 開発者が発行してお渡しします |
| サーバーに送るか | **送りません** | 送ります（どのクラスかを判別するため） |
| 何のためか | 学校の経路に入るため | クラスの合計を出すため |
| 形 | 自由（例: `sakura-2026`） | `ABCD-EFGH` の8文字 |

**クラスコードに学校名やクラス名は入りません。** 開発者が機械的に作った
記号なので、コードそのものから学校が分かることはありません。

クラスの合計では、**誰が何をしたかは表示されません。** 出るのはクラス全体の
合計と、自分の分だけです。参加している人数が少ないうちは、
**引き算で個人が分かってしまうため合計も出しません。**

## 配るときに埋めるところ

`01` と `02` の `［　］` はすべて空欄です。

- 学校名
- 日付
- 学校の担当者名・連絡先
- 開発者名・連絡先（`03` と `04`）

**このリポジトリには埋めた版を置かないこと。**

## 印刷して配る場合

Markdown のままでは配れないので、PDF か紙にします。

```powershell
# 例: pandoc がある場合
pandoc 01-保護者むけ説明.md -o 保護者むけ説明.pdf --pdf-engine=wkhtmltopdf
```

`<!-- -->` のコメントは出力に出ません（配る相手に見せる文ではないので、そのままで問題ありません）。

# 学校導入のリリース判定

最終確認: 2026-08-10

> [!warning]
> **外部AI・学校サーバを使う学校導入は現在 NO-GO。** 学校コードや保護者同意だけでは解除しない。
> 通信しない端末内モードは実装済みだが、学校配布・授業利用は下記の実機監査と学校側承認まで開始しない。
> この文書は実装・運用の判定基準であり、法務助言ではない。

## いま止める理由

1. [Google Cloud Service Specific Terms §20(d)](https://cloud.google.com/terms/service-terms)
   は、生成 AI サービスを18歳未満向け、または18歳未満がアクセスし得るアプリで
   使わせないよう定めている。年齢選択で利用者だけを止めても、中高生向け製品で
   ある限り解消しない。
2. [Upstash DPA §12.4](https://upstash.com/static/trust/dpa.pdf) は、16歳未満の子どもの
   Personal Data を Upstash に提供しないよう定めている。学校・クラスとの結び付き、
   端末由来 ID、利用状態を扱う現構成は、学校導入前に契約確認または保存先移行が必要。
3. 現在のクラス機能は匿名合計の小規模機能であり、学校テナント、教職員認証、権限、
   監査、年度更新、削除依頼、一括ライセンスを備えた学校管理基盤ではない。

## worktreeに実装済みの安全側の挙動

- 18歳未満と学校経路では、同意を保存せず会話を開始しない。
- 年齢未選択・18歳未満・学校・成人のいずれも、越境送信へ同意せず端末内モードを選べる。
- 端末内モードのWidget treeには、DeviceIdentity、Live/Director、Team、RevenueCat、
  subscription-syncのProvider自体を置かない。同梱教材専用の`UnitsClient`だけを明示注入する。
- 端末内モードは、教材→想起→条件/理由→具体場面→固定チェックポイントまで進めるが、
  自由記述を送信・保存・自動採点せず、習得認定や会話枠も更新しない。
- 継続のため、教材ID・概念ID・完了回数・最終完了日時だけを端末内に保存する。
  年齢、同意、端末ID、自由記述、誤答内容は含めず、画面から全履歴を削除できる。
- 学校経路を有効化する環境変数や隠しスイッチを作らない。
- 学校経路では個人向け Plus 購入を表示しない。
- Vercel production / preview では、生成 AI API、学校 Team API、Plus 同期・
  RevenueCat webhook・アンケート回答保存をコード上で常に `503` にする。
  環境変数を追加しても公開環境では解除できない。
- ローカルまたは Vercel development の内部テストだけ、AI、学校機能、制限対象の
  データ処理を3つの独立した明示フラグで開ける。
- 音声、逐語、自由記述、本人が話した文を学校の集計基盤へ送らない。

外部AI側の停止は誤利用を防ぐ一時措置であり、Google の年齢制限を満たした公開状態を
意味しない。外部AIを中高生向けに再開する前に、下記 Phase 0 を完了する。
端末内モードだけを学校へ出す場合も、通信しないことをexact buildで実査し、教材・端末・
アクセシビリティ・授業運用を学校側と合意するまでは「学校導入済み」と扱わない。

> [!danger]
> **2026-08-10現在、上記の安全差分はVercel productionへ未デプロイ。**
> 稼働中の旧本番は匿名register後の`GET /api/live-token`が200を返し、
> Team summaryも新guardの503ではない。明示承認を得て緊急停止だけをデプロイし、
> 入口の503と依存処理zero-callを本番で確認するまで、学校や未成年へ配布しない。

## 学校版の製品境界

個人版の画面へ先生用メニューを足すのではなく、学習コアだけを共有し、購入・認証・
管理・データを分離する。

| 領域 | 個人版 | 学校版 |
|---|---|---|
| 利用資格 | 本人の同意 | 学校テナントへの在籍・配布確認 |
| 課金 | Store / RevenueCat | 学校との一括契約。生徒へ購入を出さない |
| 端末 | 個人端末 | 原則 MDM 管理端末。BYOD は別要件 |
| 管理者 | なし | 教職員アカウント、MFA、役割別権限 |
| 先生に見せる情報 | なし | 概念別の未着手・再挑戦・定着の集計 |
| 見せない情報 | — | 音声、逐語、自由記述、個人ランキング、他生徒との比較 |
| 退会・年度更新 | 端末データ削除 | 転出・卒業・年度更新・共有端末初期化 |

### 外部AIなしで先に検証できる最小構成

- 学校所有の検証端末を機内モードまたは監査用ネットワークへ置く
- クリーンインストール後、同意・年齢・端末IDが保存されない端末内モードだけを使用する
- 同梱した4単元11概念だけを対象にし、先生が授業内で教材との自己確認を支援する
- 固定3択の完了を成績・習得証明・個人評価へ使わない
- MDM配布、外向き通信ログ、共有端末初期化、200%文字と読み上げをexact buildで確認する

この構成は生成AI学校版の代替ではなく、ローカル教材と学習行為の小規模な運用検証である。

## 実装順

### Phase 0 — 外部契約と処理基盤

- [ ] 未成年・学校利用を許可する AI 提供元または書面契約を確定する。
- [ ] OpenAI Realtimeを候補にする場合は、[Under 18 API Guidance](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance)
  に従い、対象年齢に必要なZDR承認、年齢に応じたフィルタ、監視・報告・
  エスカレーション、年齢確認、最新の安全ツール/モデルを実装・運用条件として固定する。
- [ ] 16歳未満のデータを扱える保存先または Upstash との書面特約を確定する。
- [ ] 既存のアンケート・Team・利用枠・entitlement記録を棚卸しし、必要な保全を
  確認したうえで、現保存先から削除または適格な保存先へ移行する。
- [ ] 音声・逐語の保存有無、処理地域、保持期間、再委託先をデータフロー図に固定する。
- [ ] 学校との利用契約、DPA、障害連絡、削除期限、サポート窓口を法務確認する。

### Phase 1 — 学校コントロールプレーン

- [ ] `tenant / school / class / enrollment / school_license` を端末 UUID から分離する。
- [ ] 教職員を学校 IdP の OIDC/SAML で認証し、MFA と `admin / teacher / support` の
  最小権限を設ける。
- [ ] 学校コードは短期・単回または管理配布された署名付き登録情報にし、学校承認や
  保護者同意の証跡そのものとして扱わない。
- [ ] 管理操作、閲覧、CSV 出力、削除を監査ログへ残す。
- [ ] 同一端末から同じクラスへ複数回参加しても定員超過しないよう、参加処理を原子的にする。

### Phase 2 — 教員 UX と授業運用

- [ ] 課題を学年・単元・概念・期限で配布できる。
- [ ] 先生には許可された派生状態だけを表示し、少人数では集計を隠す。
- [ ] 生徒を点数・順位・連続日数で競わせない。学習ループは
  `教える → 思い込みを見破る → 理由で直す → 別の場面で再挑戦` を維持する。
- [ ] 欠席、途中参加、共有端末、通信断、授業終了時の一括停止を扱う。

### Phase 3 — 配布・運用

- [ ] iOS Managed Distribution / Android Enterprise の Managed Configuration で、
  学校テナント、API 環境、機能制限を端末へ配布する。
- [ ] 学校版では個人向け Store 購入、クラス退出、外部共有を管理設定で無効化できる。
- [ ] 卒業・転出・端末返却時のデータ削除を自動化し、学校へ完了記録を返す。
- [ ] 稼働状況、障害、費用上限、AI 安全性の変更を学校単位で通知する。

## 学校版を有効化する受入条件

- Google/AI 提供元と保存先について、対象年齢と学校利用を許可する根拠が書面で残っている。
- 生徒端末だけで学校経路を自己申告して有効化できない。
- 先生・管理者の全 API が学校テナント境界と役割を検証する。
- 別学校のデータを ID 置換で読めないことを統合テストで確認する。
- 音声・逐語・自由記述が学校集計 API、ログ、分析基盤へ入らないことを検査する。
- 個人 Store 課金が学校経路に表示・起動されない。
- 共有端末の利用終了でローカル逐語・認証情報・学校所属を消去できる。
- [文部科学省の教育情報セキュリティポリシーに関するガイドライン](https://www.mext.go.jp/a_menu/shotou/zyouhou/detail/1397369.htm)
  と導入先自治体・学校のポリシーに対する確認記録がある。

## 先に決める運用条件

推奨の初期構成は、学校所有端末、MDM 配布、学校一括契約、クラス集計のみ。
BYOD を使う場合は、家庭アカウントとの混在、端末紛失、卒業後のデータ分離、個人課金の
扱いが変わるため、同じ受入条件では開始しない。
